# Security Policy

Security is a core priority for the LifyX ecosystem.

If you discover a security vulnerability affecting any LifyX repository, application, integration, developer resource or public service, please report it responsibly.

## Reporting a Vulnerability

Please do not publicly disclose security vulnerabilities through:

- GitHub Issues
- Discussions
- Pull Requests
- Public social media posts

Instead, report security concerns privately to:

security@lifyx.exchange

If the security email is unavailable, contact:

support@lifyx.exchange

## What to Include

When reporting a vulnerability, please include as much relevant information as possible:

- A clear description of the issue
- Affected repository, service, endpoint or component
- Steps to reproduce the issue
- Potential impact
- Screenshots or logs when relevant
- Suggested remediation, if available

Do not include private keys, seed phrases or other sensitive credentials in reports.

## Sensitive Information

Never share:

- Private keys
- Seed phrases
- Wallet passwords
- API secrets
- Access tokens
- Environment secrets
- Production credentials

If sensitive credentials are accidentally exposed, they should be revoked and replaced immediately.

## Responsible Disclosure

We ask security researchers and developers to:

- Avoid accessing or modifying user data
- Avoid disrupting production services
- Avoid destructive testing
- Avoid social engineering
- Allow reasonable time for investigation and remediation before public disclosure

## Scope

Security reports may include issues affecting:

- LifyX repositories
- LifyX developer documentation
- API examples
- Web3 utilities
- Spot integrations
- Perpetual integrations
- Wallet integrations
- Trading interfaces
- Public endpoints
- Developer resources
